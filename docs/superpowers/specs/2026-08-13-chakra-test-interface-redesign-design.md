# 脉轮测试界面改版设计

- 版本：1.0
- 日期：2026-08-13
- 状态：待书面规格确认
- 项目类型：连续问卷与结果报告
- 改造层级：三级体验重构
- 设计依据：`E:\圆圆如意官网\docs\design-system.md`

## 1. 文档目的

本文档定义脉轮测试欢迎页、连续答题页、结果报告及共用主题框架的完整改版方案。它把已经确认的视觉稿转化为可实施、可验证的产品规格，避免实施阶段只照着单张截图还原，遗漏主题状态、恢复流程、可访问性或业务边界。

本次改版保留当前测试和结果计算能力，重建展示层与交互层。设计目标不是把官网首页原样搬入测试，而是在品牌底线下，为长时间作答和结果阅读建立更清楚的界面。

视觉确认稿位于 `.superpowers/brainstorm/`，只作为设计证据，不是正式运行时依赖。确认稿为了比较同时展示浅色和深色；正式产品在任一时刻只显示用户当前选择的一个主题。

## 2. 背景与问题

当前界面能够完成开始、续答、计分、结果保存和分享，但存在以下体验问题：

- 全屏紫色渐变、毛玻璃、多彩光晕和持续脉冲成为全局视觉，弱化圆圆如意的品牌识别；
- 欢迎、答题、结果三屏均集中在 `src/app/page.tsx`，业务状态与展示细节耦合，改版容易误伤恢复、提交和重测行为；
- 答题选项缺少单选组语义，选中状态主要依赖颜色，自动前进后焦点去向不明确；
- 结果页连续堆叠玻璃卡片，结论、数据、人物参考和次级转化的层级不清；
- 正式人物原型图被额外画框、渐变和阴影包裹，和素材自身卡片结构重复；
- 主题、减少动态、分享反馈、数据库保存失败等状态缺少一致规则。

## 3. 目标与非目标

### 3.1 目标

1. 建立可切换且可持久化的浅色、深色双主题，三屏使用同一主题。
2. 以“东方编辑式、成熟克制、温柔有力”为视觉方向，恢复圆圆如意品牌识别。
3. 欢迎页只保留一个清楚的主行动，并明确新测试与续答两种状态。
4. 答题页形成窄容器、单列、低干扰的连续作答路径，并补齐键盘和辅助技术支持。
5. 结果页以“结论 → 摘要 → 人物参考 → 数据 → 深度分析 → 次级转化”组织长报告。
6. 保留并放大正式女性人物原型卡，去除网页额外画框，避免视觉重复。
7. 保持当前测试、计分、原型映射、本地恢复和部署契约不变。
8. 在桌面、窄桌面和低高度手机上都能完成核心流程，无横向溢出或底栏遮挡。

### 3.2 非目标

- 不修改 56 道题、题目顺序、5 档选项文本或每题正反向得分。
- 不修改七轮分数范围、归一化方式、原型映射、最高两轮/最低轮和平局规则。
- 不修改 API 请求体、数据库结构或 PostgreSQL 部署方式。
- 不引入用户账户、云端跨设备续答、性别选择、国际化或原生社交分享。
- 不切换到男性人物图、Q 版候选图或未确认素材。
- 不在本次视觉改版中修正文案所涉及的题库解释或结果算法。
- 不建立跨仓库组件包；只在本项目内建立清楚的主题和页面组件边界。

## 4. 核心设计原则

### 4.1 任务优先

欢迎页可以保留品牌开场，答题页优先连续阅读，结果页优先结论与依据。三屏共享品牌语言，但不强求相同密度或相同构图。

### 4.2 品牌色负责界面，脉轮色负责数据

页面背景、文字、边界和主操作使用品牌令牌。七种脉轮色只出现在七轮几何图、当前章节、进度和结果数据中，不作为全站主按钮、通用文字或整屏背景。

### 4.3 单一主操作

每个状态只有一个漆器红主操作：无进度欢迎页为“开始测试”，有进度欢迎页为“继续测试”，最后一题为“查看结果”。重新开始、暂存退出、分享和咨询均按场景降为次操作或文字操作。

### 4.4 状态不只靠颜色

选中、成功、失败、禁用和当前步骤均同时使用文字、边界、形状或位置表达。颜色只提供辅助线索。

### 4.5 内容先于装饰

不使用全屏紫粉蓝渐变、毛玻璃卡片、多彩发光团、持续脉冲和无意义骨架屏。东方感通过宣纸色、墨色、字体、细线、比例和有节奏的留白形成。

## 5. 视觉系统

### 5.1 品牌与主题令牌

品牌基础色保持跨项目标准：

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| `--yyry-ivory` | `#F3EDE3` | 浅色页面背景 |
| `--yyry-paper` | `#FAF7F1` | 浅色内容纸面、深色主文字 |
| `--yyry-lacquer` | `#8E1F29` | 品牌强调、主操作、浅色焦点 |
| `--yyry-ink` | `#151716` | 浅色主文字、深色面 |
| `--yyry-stone` | `#CDBAA4` | 细边界、柔和分区 |
| `--yyry-champagne` | `#A78150` | 非文本装饰、较大编号和细节线条 |
| `--yyry-muted` | `#74695F` | 浅色次要正文 |

项目语义令牌如下。组件只使用语义令牌，不在局部重复写主题色值。

| 语义 | 浅色主题 | 深色主题 |
| --- | --- | --- |
| 页面背景 | `#F3EDE3` | `#131412` |
| 内容纸面 | `#FAF7F1` | `#171816` |
| 主文字 | `#151716` | `#FAF7F1` |
| 次文字 | `#74695F` | `#C9C2B8` |
| 辅助文字 | `#74695F` | `#A59D93` |
| 细边界 | `stone` 约 55% 混合透明 | `paper` 约 14% 透明 |
| 主操作 | `#8E1F29` | `#8E1F29` |
| 主操作文字 | `#FAF7F1` | `#FAF7F1` |
| 焦点环 | `#8E1F29` | `#E7BCC0` |

核心文字组合的对比度至少满足 WCAG AA：浅色主文字/宣纸约 15.47:1，浅色次文字/宣纸约 4.59:1，深色主文字/近黑约 17.28:1，深色辅助文字/近黑约 6.90:1，按钮文字/漆器红约 8.26:1。

浅色主题的 `11–13px` 英文眉题使用漆器红或次文字色，不使用 `#A78150`；香槟铜在小号文本上对比不足，只可用于不承载信息的细线、圆点或足够大的装饰编号。深色主题的英文眉题使用 `#E7BCC0` 或深色次文字。

### 5.2 七轮业务色

为降低饱和度并与品牌纸面协作，界面层使用以下业务色；题库原始颜色值与计分数据不需要改变。

| 脉轮 | 界面色 |
| --- | --- |
| 海底轮 | `#B44E45` |
| 脐轮 | `#C77A43` |
| 太阳轮 | `#CDA645` |
| 心轮 | `#6D9275` |
| 喉轮 | `#5C8798` |
| 眉心轮 | `#62658A` |
| 顶轮 | `#896E90` |

颜色必须与名称、题号、数值或文字结论共同出现。结果图表不要求用户通过颜色猜测类别。

### 5.3 字体

| 职责 | 字体 | 场景 |
| --- | --- | --- |
| 中文展示 | `Noto Serif SC` 400 | 品牌名、页面标题、题目、结果结论、引语 |
| 中文正文 | `Noto Sans SC` 400 | 正文、导航、按钮、选项、数据说明 |
| 英文展示 | `Cormorant Garamond` 400 | 英文眉题、章节名、编号、人物英文名 |

正式实现复用官网已核验的 `noto-serif-sc-home-400.woff2`、`noto-sans-sc-home-400.woff2` 和 `cormorant-garamond-latin-400.woff2`，将它们复制到本项目受版本控制的 `public/fonts/`，通过 `@font-face` 加载并设置合理回退。字体加载失败时仍可使用 `SimSun`、`Microsoft YaHei` 等回退完成任务。不得从运行时外链字体服务加载。

建议字号：欢迎页主标题桌面 `56–68px`、移动 `42–48px`；答题题干桌面 `28–34px`、移动 `24–28px`；结果原型名桌面 `38–48px`、移动 `32–38px`；正文 `15–17px`；辅助文字 `12–14px`；英文眉题 `11–13px`，字距 `0.16–0.22em`。

### 5.4 布局、间距和形状

- 欢迎页内容宽度最大 `1120px`，答题页最大 `760px`，结果报告最大 `1120px`。
- 桌面水平安全边距 `32–48px`；移动端不小于 `16px`。
- 间距只从 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 80px` 中选择。
- 静态报告章节以留白和 1px 细线分区，不给每段文字套卡片。
- 大内容面板和人物图默认直角或素材自带圆角；答题选项使用 `8px` 圆角；状态标签可使用全圆角。
- 常规内容无阴影；只有固定导航或真实浮层允许轻阴影。
- 同一页面主要圆角不超过两级。

### 5.5 动效

- 首次进入页面仅允许标题、说明和七轮图形在 `250–450ms` 内轻淡入，可有不超过 `8px` 的短位移。
- 选项反馈为 `150–250ms`；选择后等待约 `250ms` 再进入下一题。
- 页面状态切换使用 `200–300ms` 淡入淡出，不做大幅横向飞入。
- 主题切换只改变颜色令牌，不给整页添加长时间过渡。
- 不使用持续脉冲、循环发光、弹跳、无意义缩放或长时间离场动画。
- `prefers-reduced-motion: reduce` 下取消非必要位移、缩放、平滑滚动和循环动画，内容直接出现；自动下一题这一业务行为仍保留。

## 6. 主题系统

### 6.1 主题优先级

主题值只有 `light` 和 `dark`，优先级固定为：

1. 用户曾手动选择的本地主题；
2. 若没有手动选择，读取 `prefers-color-scheme`；
3. 无法读取时回退到浅色。

本地存储键使用新的版本化键，例如 `chakra-test-theme-v1`，不与答案和结果键混用。

“跟随系统”只描述从未进行手动选择的初始策略，不是界面中的第三个可选主题。若未来需要让用户恢复系统跟随，应另行设计三态设置；不在本期范围内。

### 6.2 跟随系统与持久化

- 用户从未手动切换时，系统主题变化应实时更新页面。
- 用户第一次手动切换后，持久化选择并停止跟随系统；此后每次操作只在浅色和深色之间切换。本版本不提供“跟随系统”第三态或恢复入口。
- 欢迎、答题和结果共用根节点主题类；页面切换、刷新、续答和重测均不重置主题。
- “重新测试”和“重新开始”只清除答案/结果，不清除主题。

### 6.3 首屏防闪烁

在根布局 `<head>` 中放置最小内联主题初始化脚本，在 React 接管前读取本地主题或系统主题，并把 `light`/`dark` 类和 `color-scheme` 写到 `<html>`。脚本只处理主题，不读取答案、结果或其他隐私数据。这样避免服务端默认浅色、客户端再跳深色的明显闪屏。

### 6.4 主题开关

- 位于精简品牌导航右侧，触控区域至少 `44×44px`。
- 以可访问按钮实现，名称根据动作表达为“切换到深色模式”或“切换到浅色模式”，并用 `aria-pressed` 或等价状态表达当前主题。
- 图标不是唯一线索；桌面显示“浅色/深色”文字，移动端可只保留图标，但必须保留可访问名称。
- 键盘可用 `Tab` 聚焦，以 `Enter` 或空格切换。

## 7. 全局页面框架与组件边界

正式实现应把当前单文件页面拆为以下职责明确的单元，具体文件名可在实施计划中微调：

| 单元 | 职责 |
| --- | --- |
| `ThemeProvider` / `ThemeToggle` | 主题初始化、系统跟随、手动持久化和开关 |
| `TestShell` / `BrandHeader` | 三屏共用的页面背景、精简导航和内容安全区 |
| `WelcomePage` | 新测试与续答入口，不直接管理存储 |
| `QuestionPage` | 单题显示、单选组、进度和底部操作 |
| `ResultPage` | 把动态原型数据组织为章节，不负责计分 |
| `useTestSession` 或同等状态层 | 恢复、保存、开始、继续、退出、提交和重测 |
| `ChakraArchetypeAvatar` | 正式人物图路径、比例、加载失败占位 |

`src/lib/chakra-data.ts` 和 `src/lib/chakra-archetypes.ts` 继续作为题库、计分和原型计算的唯一来源。展示组件不能复制或重新实现算法。

精简导航在三屏保持品牌归属：左侧“圆圆如意”，桌面中间显示 `Chakra Archetype Test` 或当前报告名称，右侧放当前场景动作和主题开关。移动端隐藏中间英文名；答题页保留“退出”和主题图标，结果页只保留主题图标，分享与重测使用报告后段的完整操作组，不能让导航动作挤压品牌名。

## 8. 欢迎页

### 8.1 无未完成进度

页面从上到下为：

1. 精简品牌导航；
2. 英文眉题 `Chakra Archetype`；
3. 主标题“看见你的能量秩序”；
4. 一句说明“沿着七种能量线索，读出你此刻的主导力量、辅助风格与成长课题。”；
5. `56 道题 / 约 5–10 分钟 / 可中途续答` 三项元信息；
6. 唯一主按钮“开始测试”；
7. 低优先级文字入口“测试如何进行”，在当前页展开一段说明，内容固定为题量、预计用时、同设备续答和非诊断用途，不新建路由或弹窗；
8. 右侧无文字七轮同心几何图。

七轮图由三层细圆环、七个低饱和度业务色节点和无文字中心几何组成。中心不得再出现“如”字或其他文字。图形是装饰性品牌隐喻，读屏时可整体隐藏；页面正文已经提供等价含义。

### 8.2 有未完成进度

未完成进度优先于旧结果。欢迎页保留标题、说明、元信息和七轮图，但移除 Hero 操作区，在 Hero 后显示横向续答信息带：

- 标题：“继续上一次探索”；
- 内容：“已完成 X / 56 题 · 进度仅保存在当前设备”；
- 主操作：“继续测试”；
- 文字操作：“重新开始”。

“继续测试”只出现在续答信息带，是该状态唯一的漆器红按钮；Hero 不再重复显示“开始测试”或“继续测试”。

“重新开始”会清除当前未完成答案和旧结果，留在欢迎页；执行前使用轻量确认对话框，明确“这会清除当前设备上的答题进度”，避免误触。确认不是危险的永久远端删除，不使用夸张警告色。

### 8.3 响应式

- 桌面 Hero 为文案和七轮图两栏，图形约 `230px`。
- 小于 `768px` 后转为单列，图形作为右上低对比装饰，不遮挡文字和按钮。
- 续答信息带在移动端改为纵向；按钮占满可用宽度，文字操作单独一行。
- `prefers-reduced-motion` 下图形和内容直接显示。

## 9. 答题页

### 9.1 信息顺序

答题页采用最大 `760px` 的单列阅读路径：

1. 精简导航：品牌、测试名、主题开关、“暂存并退出”；
2. 当前脉轮和分组、题号 `X / 56`、百分比；
3. 一条进度条；
4. 英文脉轮章节名和简短主题；
5. 题目编号与题干；
6. 五个回答选项；
7. 辅助说明；
8. 底部第一行保存状态，第二行“上一题 / 下一题或查看结果”。

当前脉轮色只用于章节小标和进度条已完成部分。主按钮仍使用漆器红。

### 9.2 选项状态

五个选项按当前 `optionLabels` 动态渲染，不改成视觉稿中的示意文案。选项使用 `radiogroup` / `radio` 语义；优先复用已安装的 Radix Radio Group，或使用等价原生语义。

选中态同时具备四个线索：

- 边框提高到漆器红或深色主题对应强调色；
- 背景出现低透明度强调色；
- 左侧序号圆形填充；
- 右侧显示“已选择”与勾选符号。

未选项悬停只轻微改变边框或底色，不缩放整块选项。焦点环独立于选中边框，不能因选中而消失。

### 9.3 自动前进与手动导航

- 用户通过鼠标或触控选择后，先同步更新内存状态并立即写入本地进度，再等待约 `250ms` 自动进入下一题；最后一题不自动提交。
- 自动前进计时器必须可取消。用户在等待期间点击“下一题”“上一题”“暂存并退出”、重新选择或组件卸载时，取消旧计时器，避免跳过题目。
- 进入新题后，把焦点移到新题标题；用简短 `aria-live` 文本播报“第 X 题，共 56 题”。
- 返回上一题时显示原答案；修改后覆盖该题答案，分数只在最终提交时按当前答案重新计算。
- “下一题”在当前题未选时禁用；最后一题改为“查看结果”。
- 提交前验证 56 题全部有合法答案。若存在遗漏，不提交、不清空进度，并跳到第一道未答题，显示“还有 X 题未完成”。

键盘遵循单选组惯例：方向键移动并更新选中项，空格选择当前项；两种操作都立即保存，但不触发自动前进。键盘用户通过底栏“下一题”或“查看结果”明确前进。这一差异需在键盘提示中说明，避免纯键盘用户在浏览选项时意外跳题。不要依赖非标准的 Radio `Enter` 行为，也不要在 `onValueChange` 中无条件启动自动前进。

### 9.4 暂存并退出

“暂存并退出”明确保存当前答案和题号，然后回到欢迎页的续答状态。退出不是清空。保存成功以导航旁或底栏的“答案已保存到当前设备”呈现，不使用每题弹出的 toast 干扰连续作答。

桌面保存状态可位于导航或底栏中间；移动端固定底栏使用独立的第一行居中显示保存状态，第二行只放上一题和下一题/查看结果，状态文字不得挤压两个操作按钮。

若本地存储不可用，页面仍允许继续本次会话，但在答题页固定提示“当前浏览器无法保存进度，关闭页面后可能丢失”；“暂存并退出”改为“退出测试”，并在操作前说明后果。

### 9.5 移动端底栏

- 小于 `768px` 时底部操作区固定，左右为上一题和下一题/查看结果。
- 底栏包含 `env(safe-area-inset-bottom)`，正文底部预留“底栏实际高度 + 24px”的空间。
- 不要求题干和五个选项挤在一屏；正文自然滚动，最后一个选项完全可见并可聚焦。
- 低高度 `375×667` 设备上隐藏非关键英文说明，但不隐藏题号、进度、题干、选项和导航。

## 10. 结果报告

### 10.1 章节顺序

结果页最大宽度 `1120px`，按以下顺序组织：

1. 精简报告导航；
2. 报告标题与用途说明；
3. 人物原型结论和正式人物图；
4. 四项核心摘要；
5. 独立“代表人物参考”章节；
6. 七轮数据与文字依据；
7. 深度分析和成长方向；
8. 分享、二维码咨询与重测；
9. 免责声明和品牌署名。

视觉确认稿中的“人形安全屋”、张桂梅、特蕾莎修女和弗雷德·罗杰斯只是一个真实数据示例。正式页面必须从 `generateChakraArchetypeResult(scores)`、`femaleArchetypeCardCopy` 和当前原型的 `celebrities` 动态读取，不能全局硬编码。

### 10.2 人物原型首段

桌面首段使用约 `0.68 : 1.32` 的文案/人物图比例，让正式人物图成为首屏主要视觉。左侧显示原型家族、展示名、原型名和一句核心引语；只保留有业务意义的状态标签，不重复图片内已经烘焙的标题。

人物图规则：

- 继续使用正式女性原型图和当前 `/chakras/archetypes/female/{slug}.png` 命名契约；
- 使用完整横向比例和 `object-contain`，不得裁切图片内文字或角色；
- 网页外层不再添加边框、彩色衬底、渐变、阴影、光环或内边距；
- 图片容器与图片本身边界重合，只保留素材自身白色画布和内部圆角卡片；
- 桌面可用宽度不小于约 `52%` 的首段内容区，移动端宽度为容器 `100%`；
- 图片加载失败时显示同等比例的克制占位，文字为“人物原型图片暂时无法显示”，并保留结果名称，不能用“图片生成中”误导用户。

### 10.3 四项核心摘要

紧接首段展示：

- 主导能量：最高轮及原始正负分；
- 辅助风格：第二高轮及原始正负分；
- 成长课题：最低轮及原始正负分；
- 整体结构：现有能量结构名称和平均分。

桌面四列，移动端两列。摘要通过细线和 3px 业务色标识分隔，不做四张悬浮卡。不得把“代表人物参考”塞入摘要占位。

### 10.4 代表人物参考

该内容必须是四项摘要后的独立章节，不作为徽标、普通标签或摘要字段重复出现。

章节左侧显示标题、英文眉题和固定边界说明：

> 仅用于帮助理解该原型呈现出的公众气质，不代表对人物真实性格、经历、成就或心理状态的判断。

右侧动态显示当前原型的最多三位人物，中文名为主，存在 `enName` 时在下方显示英文名。桌面三列，移动端单列。若某原型没有人物数据，隐藏人物列表并显示“当前原型暂无人物参考”，但保留用途说明；不从其他原型补齐。

### 10.5 七轮数据与依据

结果数据同时显示名称、业务色、原始 `-100..100` 正负分和必要的文字结论。桌面可以使用横向条形图或等价 CSS 条形图；移动端必须无需悬停即可读出全部名称和数值。

图表要求：

- 0 为明确中线；正负方向可见；
- 不使用立体效果、阴影、渐变或大面积网格线；
- 主导、辅助和最低轮可用文字角色标注；
- “优势如何形成”直接读取现有 `archetypeResult.strengths`，“需要留意什么”直接读取 `archetypeResult.shadow`，深度分析公开摘要读取 `archetypeResult.summary`；不得硬编码视觉稿示例或另造算法；
- Tooltip 只能补充信息，不能承载唯一信息；
- 为读屏器提供同顺序的文本列表或表格等价内容。

### 10.6 深度分析与次级转化

深度分析先展示当前已有的公开摘要和罕见原型提示。更多分析的边界使用真实文字说明，不再用模糊骨架屏伪装尚未开放的内容。

现有 `relationshipMode`、`workMode` 和 `recommendations` 继续属于咨询后可展开的更多分析，本期结果页不直接展示其完整内容。

桌面精简报告导航可提供低强调的“分享结果”和“重新测试”文字快捷入口，并保留主题开关；两者必须是无填充的文字按钮。完整的分享、二维码咨询和重测操作组位于结果主体之后，其中“复制分享摘要”为唯一漆器红主按钮，“重新测试”为次按钮，咨询由二维码区承载。顶部快捷入口与底部操作调用同一行为，不创建第二套状态。移动端隐藏顶部分享与重测快捷入口，只保留报告后段的完整操作：

- 分享继续复制现有原型摘要、代表人物和链接，不宣称打开微信原生分享；
- 复制成功显示“已复制，可粘贴分享给好友”，使用 `aria-live="polite"` 播报；
- Clipboard API 不可用时保留当前受控文本复制回退；若两种方式都失败，显示可选中的分享文本和明确失败提示；
- 二维码使用现有 `public/qrcode.png`，替代文字为“添加圆圆微信以咨询完整分析的二维码”；
- 二维码区域保持白底以确保扫描，但不套多层卡片；
- “重新测试”为次按钮，清除进度和结果后回到欢迎页，不清除主题；
- 免责声明保留当前非医疗、非心理诊断与专业求助边界。

## 11. 状态流与数据流

### 11.1 启动恢复

启动时分别读取主题、答案进度和本地结果。主题仍由 `<head>` 初始化脚本在 React 接管前完成；答案与结果只能在客户端挂载后读取。页面状态增加仅用于初始化的 `booting` 状态：恢复完成前渲染同主题的精简品牌外壳和“正在恢复测试”短状态，不先渲染欢迎页，也不使用伪内容骨架。恢复完成后再进入 `welcome`、`test` 或 `result`。

恢复顺序与优先级为：

1. 主题独立初始化；
2. 校验本地答案和当前题号；
3. 若存在 `1–55` 道合法答案，显示欢迎页续答状态；
4. 若存在 56 道合法答案但没有本地结果，显示“答案已完成，待查看结果”的续答状态；继续时定位第 56 题，保留答案并直接提供“查看结果”，不得恢复旧结果；
5. 仅在没有任何合法答题进度时，恢复合法的旧结果；
6. 两者都没有时显示新测试欢迎页。

恢复数据必须校验：题号 `1..56`、选项值 `0..4`、当前题索引 `0..55`、结果包含七轮分数且数值在 `-100..100`。损坏数据按最小范围清理，不因一个坏字段让页面崩溃。

### 11.2 作答保存

每次选答先更新内存，再同步尝试写入答案与当前题号。自动前进必须发生在本地写入尝试之后。页面也可在 `visibilitychange` 或卸载前做一次尽力保存，但不能依赖它作为唯一保存时机。

### 11.3 提交结果

提交逻辑由不会随 `ResultPage` 挂载或卸载而消失的会话状态层负责。提交时执行以下顺序：

1. 验证 56 题完整；
2. 克隆本次答案，用现有计算函数生成七轮分数，并创建不可变提交快照；快照包含答案、分数、完成时间和只在客户端使用的会话标识；
3. 尝试把结果快照写入本地结果；只有写入成功后才清除未完成进度；写入失败时保留答案和当前题号，在内存中继续展示结果，并提示“当前结果未能保存，关闭页面后可能丢失”；
4. 把会话层保存状态设为 `saving`，使用该快照切换结果页；
5. 会话层后台尽力请求 `/chakras/api/test-results`，成功改为 `saved`，失败改为 `failed`。

客户端会话标识只用于区分过期网络响应，不加入 API 请求体，不改变数据库结构。结果页读取会话层的结果快照和保存状态，不自行发起保存请求。

数据库保存失败不等于测试失败，不能阻塞结果展示，也不能清除本地结果。页面以低干扰状态说明“结果已保存在当前设备，在线备份暂未完成”，不要求用户重新答题。避免对同一次用户动作自动无限重试；本次范围不新增持久化重试队列。

### 11.4 重复提交与竞态

- 点击“查看结果”后立即进入提交中状态并禁用按钮，避免重复请求。
- 自动前进计时器在提交、退出和页面切换时全部取消。
- 网络响应晚于结果页出现时，只更新保存状态，不切换页面或覆盖新会话。
- 新测试和重测生成新的会话边界，旧请求不得清除新答案。

## 12. 业务逻辑与资源契约

以下行为是改版不可改变的回归基线：

- 共 56 题、7 轮、每轮 8 题、5 档回答；
- 当前每题的正向/反向得分数组与七轮原始 `-100..100` 分数；
- 原型由最高两轮决定，最低轮决定成长课题；
- 同分时继续使用 `src/lib/chakra-archetypes.ts` 中的固定轮序规则；
- 未完成进度优先于旧结果；
- 同一设备本地续答，可返回修改；
- 本地先生成结果，数据库失败不阻止结果页；
- `femaleArchetypeCardCopy` 的展示名和标题覆盖规则；
- 当前正式女性人物图，不新增性别选择；
- `/chakras` 部署前缀、API 路径、人物图路径和二维码资源；
- 复制分享、二维码咨询、重测、罕见原型提示和免责声明。

视觉改版不得在组件中硬编码某个示例结果，也不得把 `.superpowers/brainstorm/` 的图片复制为正式业务数据源。

## 13. 异常与边界状态

| 场景 | 处理方式 |
| --- | --- |
| 本地存储不可用 | 本次会话仍可答题；持续提示无法续答；退出前说明可能丢失 |
| 本地进度损坏 | 丢弃非法题目/答案；修正越界当前题；无合法答案时回到新测试状态 |
| 旧结果缺字段 | 不渲染半成品报告；清理非法结果并回到欢迎页 |
| 人物图加载失败 | 保持比例，占位显示结果名和“人物原型图片暂时无法显示” |
| 代表人物为空 | 保留章节说明，显示“当前原型暂无人物参考” |
| 数据库不可用 | 立即显示本地结果，低干扰提示在线备份失败 |
| 保存接口返回非 JSON | 按保存失败处理，不影响本地结果 |
| 重复点击提交 | 首次点击后禁用，整次会话只发起一次提交 |
| Clipboard API 不支持 | 尝试受控文本复制；仍失败时展示可选中文本 |
| 主题存储值非法 | 忽略并回到系统主题；不影响答案与结果 |
| JavaScript 主题脚本失败 | CSS 浅色为安全回退，页面仍可完成测试 |

- `src/app/globals.css`：品牌、主题、字体和基础可访问性令牌；
- `src/app/page.tsx`：保留页面状态入口，拆出展示与会话职责；
- `src/components/`：新增共用导航、主题开关、欢迎、答题和结果章节组件；
- `src/components/chakra-archetype-avatar.tsx`：新增无额外画框的结果 Hero 呈现和准确失败占位；
- `src/lib/`：只增加主题/会话辅助与输入校验，不改变计分和原型算法；
- `public/fonts/`：加入三份已核验本地字体；
- 同目录 `*.test.ts` / `*.test.tsx`、Vitest/jsdom/Testing Library 配置与 `npm test` 脚本。

实施计划应把视觉组件拆分、状态回归、主题防闪屏和浏览器验收分阶段执行，避免一次性重写 `page.tsx` 后才发现业务回归。

## 19. 最终决策摘要

- 采用同一套东方编辑式结构，提供完整浅色和深色主题；
- 首次跟随系统，手动切换后本地持久化；
- 欢迎页使用无文字七轮同心图和单一主操作；
- 答题页使用窄容器、可访问单选组、鼠标/触控选择后 250ms 自动前进和明确暂存退出；
- 结果页使用章节式人物志结构，人物图放大并去除网页额外画框；
- “代表人物参考”作为四项摘要后的独立动态模块；
- 七轮色只承担状态和数据语义，主操作继续使用漆器红；
- 数据库失败不阻止本地结果；
- 视觉改版不改变题库、计分、原型匹配、API 与 `/chakras` 部署契约。
